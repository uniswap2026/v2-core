# Uniswap V2 收益说明

## 初始创建池子（t=0）

你和别人一起提供流动性：
- 池子储备：**1000 TokenA** 和 **1000 TokenB**
- k = 1000 × 1000 = **1,000,000**
- **流动性（√k）= 1000**
- 铸造 LP token：**totalSupply = 1000**

此时：
- 你的 LP token 代表 100% 所有权。
- 你拥有的流动性价值 = 1000 / 1000 × 1000 = **1000**（完全匹配）。

## 步骤2：有人来 Swap，产生手续费（t=1）

假设经过多笔交易后，手续费累积到池子里（0.3% 的手续费会增加储备量）。

**现在池子储备变成：**
- **1060 TokenA** 和 **1060 TokenB**（为了简单，让两个 token 等比例增长）

计算新的 k 和流动性：
- 新 k = 1060 × 1060 = 1,123,600
- **新流动性（√k） ≈ 1060**

**重要变化**：
- 池子“蛋糕”因为手续费自动长大了（从 1000 → 1060）。
- 但 **LP token totalSupply 仍然是 1000**（还没铸造新 token）。
- 此时手续费已经躺在池子里，但还没分配给 LP 或协议。

## 步骤3：协议 / LP 要收手续费（触发 _mintFee）

当有人**添加流动性**或**移除流动性**时，合约会调用 `_mintFee` 来结算之前累积的手续费。

**此时计算：**
- 旧流动性 `rootKLast = 1000`
- 新流动性 `rootK = 1060`
- growth = 1060 - 1000 = 60

**铸造给协议的 LP token 数量 M**（公式）：
```
M = totalSupply × (rootK - rootKLast) / (5 × rootK + rootKLast)
  = 1000 × 60 / (5×1060 + 1000)
  = 60,000 / (5300 + 1000)
  = 60,000 / 6300 
  ≈ 9.5238
```

**铸造完成后：**
- 新 totalSupply = 1000 + 9.5238 ≈ **1009.5238**
- 协议拿到 **9.5238** 个 LP token
- 原有 LP 持有 **1000** 个 LP token（份额 ≈ 1000 / 1009.5238 ≈ 99.056%）

## 现在各方实际拥有的流动性价值是多少？

- **总蛋糕大小**现在是 **1060**
- **原有 LP 实际拥有** = 99.056% × 1060 ≈ **1050**
- **协议实际拥有** = 0.944% × 1060 ≈ **10**

**验证是否符合“协议拿增长的 1/6”**：
- 总增长 = 60
- 增长的 1/6 = 10 → 协议精确拿到 **10**
- 增长的 5/6 = 50 → 原有 LP 拿到原有 1000 + 50 = **1050**

**完美匹配！**

## 总结整个过程表格

| 阶段                  | 储备 (A,B) | √k (流动性) | totalSupply LP  | 原有LP份额  | 原有LP拥有流动性 | 协议拥有流动性 |
| --------------------- | ---------- | ----------- | --------------- | ----------- | ---------------- | -------------- |
| 创建池子              | 1000,1000  | 1000        | 1000            | 100%        | 1000             | 0              |
| Swap 后（手续费累积） | 1060,1060  | **1060**    | **1000** (不变) | 100%        | 1060（暂未结算） | 0              |
| 触发 mintFee 后       | 1060,1060  | 1060        | **1009.52**     | **99.056%** | **1050**         | **10**         |

**关键理解点再次强调**：
1. **流动性（√k）** 是蛋糕真实大小，会随手续费**自动增长**。
2. **LP token 数量** 是分蛋糕的票数，**不会自动增长**。
3. 协议通过**铸造新票**（稀释大家）来拿走增长的 1/6。
4. 公式设计得非常精妙，保证**无论 g 多大，都能精确分配**，而不是简单除以 6。

## 恒定乘积公式

- Uniswap 恒定乘积公式并不是说交易前后严格满足：`k = x * y`，
- 而是说交易定价时按照这个公式计算。
- 有手续费时，交易结束后的实际储备满足：`x * y > x_last * y_last`。
- 如果没有手续费，则满足：`k = k_last`。
